# Schema — قوانین ویکی دانش Vitalis

> این فایل قوانین ساختار/لینک‌گذاری ویکی `docs/wiki/` را نگه می‌دارد. اگر مطمئن نیستی صفحه‌ای کجا برود، همین‌جا را بخوان.

## ساختار پوشه
```
docs/wiki/
  schema.md      # همین فایل
  overview.md    # یک‌نگاه کلی محصول (≤۴۰۰ کلمه)
  index.md       # کاتالوگ همه صفحات
  log.md         # تاریخچه append-only (جدیدترین در پایین)
  entities/      # مدل‌های دیتا (Prisma) + مسیرهای کلیدی UI
  concepts/      # flowها، الگوها، تصمیم‌های معماری
  sources/        # (اختیاری) خلاصه فایل‌های خام پرارجاع
```

## شروع هر مکالمه
۱. اول `overview.md` و `index.md` (≤۸۰۰ توکن). هرگز کل کدبیس را re-scan نکن.
۲. فقط صفحات مرتبط با تسک فعلی (`entities/*.md`, `concepts/*.md`) را drill-down کن.

## وقتی کد را تغییر دادی — قانون اکید
هر بار فایلی خارج از `docs/wiki/` تغییر کرد:
۱. تشخیص بده کدام entity/concept اثر می‌پذیرد.
۲. صفحهٔ مربوطه را آپدیت کن (فیلد جدید، امضای تابع، route جدید، dependency جدید، edge case).
۳. اگر entity/concept کاملاً جدید و به‌اندازهٔ کافی مهم است، صفحهٔ جدید بساز و در `index.md` لینک بده.
۴. یک خط در `log.md` اضافه کن: `## [YYYY-MM-DD] update | <خلاصه>`.

تغییرات trivial (typo، فرمت) نیاز به آپدیت ویکی ندارند. اگر چند فایل در یک مکالمه تغییر کردند، آپدیت‌های ویکی را یک‌بار در پایان انجام بده.

## چه وقت صفحهٔ جدید بساز
- فقط اگر ≥۳ جای دیگر به آن لینک می‌دهند یا concept مستقل و حجیم است.
- در اکثر موارد صفحهٔ موجود را آپدیت کن، نه فایل جدید.
- هرگز صفحهٔ trivial نساز (wrapper یک‌خطی) — در صفحهٔ پدر یک bullet بنویس.

## ساختار صفحهٔ entity
```markdown
# {نام}

> یک‌خطی توضیح هدف.

## مسئولیت‌ها
- ...

## وابستگی‌ها
- [[concepts/xxx]] — چرا
- [[entities/yyy]] — چطور

## قراردادها / Edge cases
- ...

## منابع کد
- `path/to/file.ts:42` — توضیح
```

## قواعد لینک (Obsidian-style)
- `[[entities/user]]` بدون پسوند `.md`.
- نام فایل: lowercase + hyphen (`care-timeline.md`).
- wikilink داخل بک‌تیک/code block لینک واقعی محسوب نمی‌شود.

## Lint دوره‌ای (وقتی کاربر گفت «ویکی رو بازبینی کن»)
۱. orphan pages — لینک بده یا حذف کن.
۲. broken link — صفحهٔ گمشده را بساز یا لینک را حذف کن.
۳. تناقض بین صفحات — flag کن، بهترین حدس را انتخاب و در `log.md` ثبت کن.
۴. صفحات کهنه — بازخوانی و sync با کد فعلی.

## هماهنگی با ویکی GitHub
این ویکی (`docs/wiki/`) منبع اصلی و دقیق‌تر است (کنار کد، در همان PR دیده می‌شود). ویکی GitHub پروژه (`github.com/massoudsh/vitalis/wiki`) یک نسخهٔ خلاصه‌تر و عمومی‌تر برای مرور بیرون از IDE است. هر تغییر معنایی مهم که این‌جا اعمال می‌شود، در پایان مکالمه باید در صفحات معادل ویکی GitHub هم منعکس شود (به‌خصوص `Home`, `Architecture`, `Data-Model`, `MVP-Scope`, `Roadmap`).
